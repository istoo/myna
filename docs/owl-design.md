# Owl 界面改版规格

目标：在不丢任何功能的前提下，让 owl 的界面与 magpie 明显不同、更好认、更好用。
原则：不改配色，只改"动线"与信息组织，不动"骨"——页面结构、元素 id 与 API 不变，1192 个 GUI 回归测试继续有效。

## 一、配色：保持原版（用户 2026-11-10 定）

配色、侧栏底色、选中态、卡片质感一律沿用原版，不换主色调。
曾试过「暖纸底 + 松石绿」一版，用户评价"比原版难看"，已整版撤回。
差异化与"更好用"从交互、信息组织和动线上做，不从颜色上做。

## 二、交互（第 1 阶段，已完成）

- **侧栏搜索入口**：侧栏顶部一个「搜索… ⌘K」按钮，点开命令面板。命令面板原本只能靠快捷键发现（Linear、Raycast、Notion 的做法都是把入口常驻在侧栏顶部）。
- **⌘1–⌘9 切页**（Windows/Linux 为 Ctrl+1–9）：按侧栏顺序切到第 N 个可见页面；悬停导航项的提示里写出快捷键。浏览器标签页（owl web）里不接管，让给浏览器切标签。

## 三、第 2 阶段：页面骨架（进行中）

不改配色。目标是"一进页面就知道现在是什么状态、下一步做什么"。

1. **页头（page head）**：每个内建页面顶部一行——页面名、一句状态（如「5 个已安装 · 0 个已接入」）、右置页面级操作。
   状态从已有数据算，不新增请求。标题栏的面包屑保留（那是窗口级的）。
2. **空状态**：统一成「一句为什么 + 一个主操作」，复用 `.empty-state`；不再用灰色横条。
3. **侧栏键盘操作**：焦点在侧栏时 ↑/↓ 移动、Home/End 到首尾、Enter 打开、键入首字母跳转。

已完成：用量页空状态（`#stats .none`：时段一句话 + 为什么空 + 「接入一个 agent」「添加供应商」两个按钮，测试 `usage-empty-acts.test.cjs`）、侧栏键盘操作（`#nav` 的 ↑/↓、Home/End、首字母跳转，Enter 打开）。
未做：空状态铺到其余页面（页头状态行已在三·六完成）。

预览过的另外两个方向（未落代码，需要时按此实现并出截图）：
- 设置页内容收窄到 760px 居中，行更短、视线移动更少；
- Agent 页顶部一行状态（「5 个已安装 · 0 个已接入」）+ 快速上手折叠成一行。

## 三·五、打磨（2026-11-11，已完成）

在真界面上做“现版 vs 改进”并排对比后，用户全选落地（对比图曾放在 `docs/owl-preview/`）：
1. 侧栏图标一套：20 网格、1.6 笔画、16px 显示。Agent=终端窗口，会话=带字气泡，资源库=叠层，供应商=云，网关=两层机架带指示灯，用量带基线，脱敏=盾牌加遮罩线，插件=规整拼图，设置=同笔画齿轮。
2. 供应商行：开关用全应用通用的小号 28×16；可悬停设备上整行有 `--pill` 底色，› 右移 2px。
3. 小节名与 KPI 标签：原 11px 全大写加字距的六处改为 12px 正常大小写；10.5px 的表头、徽标、菜单分组仍保留小型大写（属于元数据）。
4. 页内搜索框 28px 高、8px 圆角。
5. 窗口最窄（560）时用量行的明细以省略号让位，花费不再被挤出卡片；手机（owl web）沿用原有的网格布局，横轴标签的避让也是原有逻辑。
测试：`nav-polish.test.cjs`（两引擎×五语言）；`mobile-web.test.cjs` 在基线没有这些改动前，会把当前页还原成基线的图标与尺寸再比较。

## 三·六、页头与 Agent 卡片（2026-11-11，已完成）

先在真界面上做 demo（现版和改版并排对比，浅色、深色、900 宽），用户说“那个最好看就选用那个”，由我选定后落地：
1. 页头（`pagehead.js`，由 navkeys.js 载入）：侧栏布局下，Agent 页和供应商页各有一个 22px 标题，下面一行状态，操作放右侧；标题栏的面包屑在这两页隐藏。
   路由、会话、插件等页面已有自己的工具栏，加大标题只会多占一行，路由页还会重复写一遍页名，所以这些页面保留面包屑。
   顶部标签布局（窄窗口、手机）不显示页头，标签本身就写着页名。Agent 页状态：「N 个已接入 · 共 N 个已安装」；
   供应商页状态：「启用 N 个 · N 个订阅已登录 · N 个模型」，查找框、账号打码、添加供应商（主按钮）移进页头。
   移进去的是页面原有元素，id 不变；页头消失时元素放回原位。
2. Agent 页：在用的 agent 改成卡片网格（每张最小 380px），图标、名称和状态、「详情」、开关在第一行，模型选择横贯整张卡，
   卡片底部一行写今日调用次数、token 和花费（`/api/usage?period=today`，只在 Agent 页可见时读取，最多 30 秒一次，
   用量页被关掉时不读）。窗口里拖拽排序改用二维的 `dragCards`，托盘面板仍是 `dragRows`。
   其余未接入的 agent 还是可展开的列表，展开后是一张整卡。
   「详情」必须留在第一行：展开的内容出现在它下方，所以它不会在指针下移动。曾经把它放在卡片底部，结果在窄窗口里收起详情时
   它会跳位，应用为了“保持点击位置”滚动页面，之后滚轮滚动也会被拉回（`view-wheel-after-redraw` 420px 红）。
3. 用量页的花费保持在原位：它的紧凑布局逻辑（#1599）依赖父元素，移进页头得不偿失。
测试：`page-head.test.cjs`（两引擎×五语言：页头、操作移入和归位、卡片并排、今日用量、拖拽换位）。

## 四、模板 v2（`docs/owl-template.html`，待用户定）

结构重排，配色原版：
- 新增「总览」首页：今日调用/花费/已接入/网关四块指标 + 开始使用清单 + 最近调用 + 供应商概览。
- 每个页面一个 22px 大标题 + 一句说明 + 右置主操作（替代标题栏里的小面包屑）。
- Agent 页改成卡片网格（每张卡：图标、名称、版本、状态徽标、模型、供应商、开关），不再是整行列表；「安装其他 Agent」是一张虚线卡。
- 快速上手压成一条三步进度条。
- 用量页：四个指标块 + 统一空状态。
- 侧栏：分组项带计数（Agent 5、供应商 3），底部一行「今日 N 次调用 · ≈$X」。
